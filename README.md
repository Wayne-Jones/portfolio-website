# Portfolio Website

Personal portfolio website for Wayne Jones — Software Engineer & Photographer based in New York, NY.

## Stack

- **Framework**: React 19 + TypeScript
- **Build**: Vite 8 + TanStack Start (SSR/SSG — static prerendering + client hydration)
- **Styling**: Tailwind CSS v4
- **Fonts**: Self-hosted Inter Variable + Switzer; IBM Plex Mono via `@fontsource`
- **Lint/Format**: Oxlint (including Tailwind CSS rules) + Oxfmt
- **Content**: Adapter pattern — Ghost CMS, committed snapshot JSON, mock fallback
- **CI**: GitHub Actions runs lint, format check, types, tests, and the build

## Routes

| Route | Description |
|-------|-------------|
| `/` | Homepage — hero, work portfolio, photography, recent posts, contact |
| `/blog` | Blog index (page 1) |
| `/blog/page/:page` | Paginated blog index (page 2+) |
| `/blog/:slug` | Individual blog post |
| `/photography` | Photo set index — masonry gallery of sets |
| `/photography/:slug` | Individual photo set |
| `/portfolio` | Work portfolio index (page 1) |
| `/portfolio/page/:page` | Paginated portfolio index (page 2+) |
| `/portfolio/:slug` | Individual project case study |

The homepage (`/`) renders a featured-photo preview, one per set; `/photography`
lists every set as a masonry gallery.

## Pagination

Blog and portfolio listings show 12 items per page. Page 1 is the bare
listing URL; later pages use `/blog/page/N` and `/portfolio/page/N`.
`/blog/page/1` and `/portfolio/page/1` redirect to the canonical listing URL,
and non-numeric or out-of-range page segments return HTTP 404. Route loaders
slice the snapshot with `paginate` and `resolvePage` from
`src/content/pagination.ts`. `vite.config.ts` enumerates every pagination path
at build time, so each page is prerendered.

## 404 handling

Detail and pagination loaders `throw notFound()` when the slug or page does not
resolve, so the response carries an HTTP 404 status while rendering the
editorial `<NotFound />` from `src/components/article/NotFound.tsx` (wired
through each route's `notFoundComponent`). The splat route `src/routes/$.tsx`
reuses the same component for any URL that does not match a route.

## Getting Started

```bash
# Install dependencies
pnpm install

# Development server (mock content)
pnpm dev

# Development server against the live Ghost CMS
# Requires a local, git-ignored `.env.ghost.local` (VITE_CMS=ghost + Ghost
# Content API vars); `vite --mode ghost` loads it.
pnpm dev:ghost

# Refresh the committed content snapshot from Ghost (requires credentials)
pnpm snapshot

# Refresh it from the mock fixtures instead (explicit opt-in)
SNAPSHOT_SOURCE=mock pnpm snapshot

# Production build + static prerender (the snapshot step runs first)
pnpm build

# Preview the built static site
pnpm preview

# Lint
pnpm lint

# Check formatting without writing
pnpm format:check

# Format
pnpm format

# Type check
pnpm exec tsc -b

# Tests
pnpm test
```

## Motion System

- **Scroll Reveal**: `[data-reveal]` elements fade/slide up on 15% visibility (IntersectionObserver)
- **Hero Entrance**: Staggered fade+slide (intro → headline → location → portrait)
- **Parallax**: Hero portrait parallax on scroll (desktop only, rAF)
- **Shimmer**: Skeleton loading animation (`.animate-shimmer`)
- **Reduced Motion**: All animations disabled via `@media (prefers-reduced-motion: reduce)`

## Fonts

Self-hosted with `font-display: optional` to avoid CLS:

- **Inter Variable** — UI text, body copy; loaded from
  `src/assets/fonts/inter` and declared in `src/styles/globals.css`
- **Switzer Variable** — Display headings, hero text; loaded from
  `src/assets/fonts/switzer`
- **IBM Plex Mono** — Code and monospace surfaces; imported from the
  `@fontsource/ibm-plex-mono` package

All fonts are served as WOFF2. Inter is subset with `unicode-range`;
Switzer ships as a single variable file.

## Content Adapter & Static Snapshot

The content layer uses a strategy pattern:

```typescript
// src/content/index.ts
export const contentService = createContentService()
```

- `GhostAdapter` — live Ghost Content API (`VITE_CMS=ghost`)
- `StaticAdapter` — committed snapshot JSON in `src/content/data/` (production builds)
- `MockAdapter` — in-repo placeholder data (development default)

Selection:
- `VITE_CMS=ghost` → Ghost
- `VITE_CMS=snapshot` → StaticAdapter anywhere
- unset → `MockAdapter` in dev, `StaticAdapter` in production builds

Every collection is sorted newest-first by `publishedAt` with `slug`/`id`
tiebreaks, both in the adapters and in the snapshot writer, so homepage
subsets, feeds, and tests do not depend on upstream response order. The
homepage uses `getRecentProjects`, `getRecentPosts`, and `getFeaturedPhotos`
(one representative photo per set).

### Snapshot workflow

The site is statically prerendered from a committed content snapshot so the
build needs no runtime access to Ghost.

1. `pnpm snapshot` fetches all posts/projects/photo sets from Ghost when
   `VITE_GHOST_URL` + `VITE_GHOST_CONTENT_API_KEY` are set and writes
   `src/content/data/{posts,projects,photosets}.json`.
2. Without Ghost credentials the snapshot step keeps the committed files and
   exits successfully, so local and preview builds stay offline and
   deterministic. `SNAPSHOT_SOURCE=mock pnpm snapshot` is the explicit way to
   regenerate the mock fixtures; `SNAPSHOT_SOURCE=snapshot` skips the fetch on
   purpose. Setting only one Ghost variable is a configuration error.
3. The snapshot is committed to git — rebuilds are deterministic and offline.
4. `pnpm build` runs the snapshot step automatically. A configured Ghost fetch
   failure fails the build without replacing the committed snapshot, so a
   partial render never ships.

### Ghost → Vercel deploy hook

To auto-rebuild when content changes in Ghost:

1. In Vercel → project → Settings → Git → **Deploy Hooks**, create a hook and
   copy the URL.
2. In Ghost admin → Settings → **Integrations → Custom webhook**, create a
   webhook pointing at the Vercel hook URL for the events `post.published`,
   `post.updated`, `post.unpublished`, and `site.changed` (do not send the
   default full payload — Vercel's deploy hook only accepts the token URL).

Vercel rebuilds, the `prebuild` snapshot refreshes content, and the new static
site deploys automatically.

## Content Rendering

Post bodies are stored as a canonical `ContentTree` (`src/content/types.ts`):
an ordered array of discriminated block nodes (`paragraph`, `heading`, `image`,
`codeBlock`, `blockquote`, `list`, `divider`, `embed`, `gallery`, `callout`,
`bookmark`, `html`) with inline marks (`text`, `link`, `emphasis`, `strong`,
`inlineCode`, `hardBreak`). Adapters translate their source format into this
tree; `<PostBody />` (`src/components/content/PostBody.tsx`) is the only
consumer.

- `GhostAdapter` parses Ghost HTML with `parse5`
  (`src/content/adapters/ghost-html-to-tree.ts`) and pre-computes Shiki
  highlighting (`src/content/highlight.ts`) before returning the tree.
- The renderer never imports Shiki or parse5, so neither reaches the client
  bundle.
- Unknown Ghost cards are preserved via the `{ type: "html" }` escape hatch and
  sanitized with DOMPurify at render time.

### Adding a new node type

1. Add the variant to the `ContentBlock` union in `src/content/types.ts`.
2. Translate it in `src/content/adapters/ghost-translate.ts` (fall back to
   `{ type: "html" }` when the pattern is uncertain).
3. Create a leaf component in `src/components/content/nodes/` that accepts the
   typed node.
4. Add a `case` for it in the `PostBody` dispatcher.
5. Run `pnpm exec tsc -b` — the dispatcher's `default: never` assertion fails
   until the new case exists.

### Cloudinary images

Set `VITE_CLOUDINARY_CLOUD_NAME` (see `.env.example`) to the Cloudinary cloud
name used by post images. `FigureImage`, `TileMedia`, and the other image
surfaces detect URLs matching
`res.cloudinary.com/<cloud-name>/image/upload/...` and emit `srcset` variants
with `c_scale,w_<N>,f_auto,q_auto`:

- **Inline images** (post bodies, galleries): `400`, `800`, `1200`, `1600`,
  lazy-loaded with a `1200w` plain `src` and the
  `(min-width: 768px) 720px, 100vw` sizes hint.
- **Detail heroes** (blog, portfolio, photo set): `priority` opts into `400`,
  `800`, `1200`, `1600`, `2400`, `3200`, `fetchpriority="high"`,
  `loading="eager"`, `decoding="sync"`, and the
  `(min-width: 1024px) 1024px, 100vw` sizes hint.
- **Blur-up placeholder**: priority Cloudinary heroes also emit a
  `w_40,e_blur:1000,q_auto,f_auto` image behind the real photo. It is removed
  once the real image loads, so the full image never depends on hydration to
  paint.
- **Layout reservation**: heroes reserve space from the image node's
  `width`/`height`; pass `aspectRatio` when a source has no intrinsic
  dimensions.

`f_auto` negotiates AVIF/WebP and `q_auto` picks a sensible quality, so the
browser downloads a smaller file for the same visual result. When the variable
is unset, or the URL points at a different cloud, images render with their
original URL and no `srcset`. `Gallery` renders each image through
`FigureImage`, so galleries get the same treatment.

Cloudinary's free tier includes 25k transformations/month. Variant URLs are
cached individually by the CDN, so only the first request for a given
width/format pays the transformation cost. If traffic grows beyond the free
tier, move to Ghost's native CDN or self-host the assets.

Snapshots in `src/content/data/` are validated against the canonical types at
module load (`src/content/validate.ts`), so a stale snapshot fails fast instead
of reaching the renderer.

## Sitemap and RSS

Every build writes `sitemap.xml` and `rss.xml` into both `dist/` and
`dist/client/` (the directory served in production). Generation runs in a
custom Vite `buildApp` plugin (`feedsPlugin` in `vite.config.ts`) after TanStack
Start finishes prerendering. `scripts/generate-feeds.ts` reads the committed
snapshot and enumerates static routes, detail routes, and pagination pages; the
RSS feed contains the 20 most recent posts. Absolute URLs use `SITE_URL` when
set, otherwise `VERCEL_PROJECT_PRODUCTION_URL` on Vercel, then
`https://waynejones.dev`.

## Performance Optimization

### Image & Asset Management

- **Photo Gallery**: Images are loaded asynchronously with lazy-loading for performance. Ensure your photo sets use WebP/AVIF format with fallback JPEG.
- **Lazy Loading**: Below-fold images benefit from native `loading="lazy"` or intersection-observer implementation on demand.

## View Transitions

Cross-page view transitions use the router's `startViewTransition` override
(`src/router.tsx`), which is disabled when `prefers-reduced-motion: reduce` is
set. Route content participates through `view-transition-name: page-content`
on `.page-content`, while the document root opts out with
`view-transition-name: none`.

## Security & Best Practices

### Content Validation
Build-time validation ensures all content adheres to type schemas:

```bash
pnpm exec tsc -b  # Type-checks the canonical content types
pnpm build        # Validates the snapshot while prerendering
```

`pnpm lint` runs Oxlint (including Tailwind CSS rules); it does not perform
schema validation. Snapshot files are validated by
`src/content/validate.ts` when the content service loads, so a stale snapshot
fails the build instead of reaching the renderer.

The adapter pattern prevents UI components from depending on specific CMS formats, ensuring forward compatibility with future content sources.

## Deployment

- Client output: `dist/client/` — one `index.html` per route
  (`/`, `/blog`, `/blog/<slug>/`, `/portfolio/<slug>/`, etc.)
- Server output: `dist/server/` (SSR bundle — optional to deploy)
- Router uses `trailingSlash: "never"`; prerender writes subfolder `index.html`
  files (`autoSubfolderIndex`).

### Vercel

`vercel.json` configures the build for Vercel:

```json
{
  "outputDirectory": "dist/client",
  "cleanUrls": true,
  "trailingSlash": false,
  "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
}
```

- Serving directory is `dist/client/`.
- `cleanUrls` strips `.html` and `trailingSlash: false` normalizes trailing
  slashes on the static files.
- The catch-all rewrite hands unmatched URLs to the root document, where the
  `src/routes/$.tsx` splat route renders the not-found UI (TanStack Router's
  default not-found is not static-host-safe).

Any static host works — the same `dist/client/` directory can be served
wherever files are static (Netlify reads `netlify.toml`/`_redirects` instead of
`vercel.json`).

```bash
pnpm build  # produces dist/client/ (static) + dist/server/
```
