# cloudinary-image-optimization Specification

## Purpose
Optimize how Cloudinary-hosted images are served across the site: format negotiation, width-based `srcset`, blur-up LQIP placeholders, and hero priority hints — all without changing the canonical `ContentTree` shape or the adapter layer.

## Requirements

### Requirement: Cloudinary URL detection

Image-emitting components SHALL detect URLs that contain the configured Cloudinary cloud name segment (`res.cloudinary.com/<VITE_CLOUDINARY_CLOUD_NAME>/image/upload/`) and SHALL emit transformed URLs using Cloudinary URL tokens.

#### Scenario: Detection requires the env var

- **WHEN** `VITE_CLOUDINARY_CLOUD_NAME` is set to a non-empty string
- **THEN** image components match URLs containing that cloud name and apply transform tokens

#### Scenario: Non-Cloudinary URLs fall back

- **WHEN** the `src` URL does not contain the configured cloud name
- **THEN** the component passes the URL through unmodified

### Requirement: Inline image srcset with width variants

When rendering an inline `image` block, the component SHALL emit a `srcset` with widths `400`, `800`, `1200`, and `1600`, generated by inserting `c_scale,w_<N>` plus `f_auto,q_auto` at the standard variant position, and SHALL use width (`w`) descriptors rather than density (`2x`) descriptors.

#### Scenario: Inline srcset contains all four widths

- **WHEN** `FigureImage` renders an inline image with a Cloudinary URL
- **THEN** the resulting `<img>` element has `srcset` containing `c_scale,w_400`, `c_scale,w_800`, `c_scale,w_1200`, and `c_scale,w_1600` entries
- **AND** each entry ends with a `400w`, `800w`, `1200w`, or `1600w` width descriptor

#### Scenario: Format and quality negotiation

- **WHEN** a Cloudinary variant URL is generated
- **THEN** it includes `f_auto` and `q_auto` so the CDN negotiates AVIF/WebP and automatic quality
- **AND** an already-transformed Cloudinary URL is passed through without another transformation segment

#### Scenario: Default sizes attribute

- **WHEN** no `sizes` prop is provided on an inline image
- **THEN** `FigureImage` renders the `sizes` attribute `(min-width: 768px) 720px, 100vw`

### Requirement: Hero image srcset with extended widths

When rendering a priority hero image, the component SHALL emit a `srcset` with widths `400`, `800`, `1200`, `1600`, `2400`, and `3200`, using width descriptors.

#### Scenario: Hero srcset contains six widths

- **WHEN** `FigureImage` renders a hero image with `priority` enabled and a Cloudinary URL
- **THEN** the resulting `<img>` element has `srcset` containing `w_400`, `w_800`, `w_1200`, `w_1600`, `w_2400`, and `w_3200` entries

#### Scenario: Extended sizes for hero

- **WHEN** no `sizes` prop is provided on a priority image
- **THEN** `FigureImage` renders the `sizes` attribute `(min-width: 1024px) 1024px, 100vw`

### Requirement: Hero priority hints

When rendering a hero image, the component SHALL set `fetchpriority="high"`, `loading="eager"`, and `decoding="sync"` on the rendered `<img>` so the browser prioritizes loading the hero before deferring other content.

#### Scenario: Hero image declares high priority

- **WHEN** `FigureImage` renders an image with `priority` enabled
- **THEN** the `<img>` element has `fetchPriority="high"`, `loading="eager"`, and `decoding="sync"`

#### Scenario: Inline image declares default lazy

- **WHEN** `FigureImage` renders a non-priority image
- **THEN** the `<img>` element has `loading="lazy"` and `decoding="async"`, and no `fetchpriority` attribute

### Requirement: Hero layout reservation

A priority hero SHALL reserve its layout box using the image's intrinsic `width` and `height` attributes when present, or an explicit `aspectRatio` override applied to the image wrapper when the caller supplies one, so the hero does not shift layout while loading.

#### Scenario: Intrinsic dimensions reserve space

- **WHEN** a priority image provides `width` and `height` on the image node
- **THEN** the rendered `<img>` keeps those `width` and `height` attributes
- **AND** no aspect-ratio override is applied

#### Scenario: Explicit aspect override

- **WHEN** `FigureImage` receives `aspectRatio="16/9"`
- **THEN** the image wrapper declares `aspect-ratio: 16/9`
- **AND** the image fills the wrapper with `object-fit: cover`

### Requirement: Blur-up LQIP via tiny blurred variant

A priority image with a Cloudinary URL SHALL render a decorative, heavily-blurred variant (`w_40,e_blur:1000,q_auto,f_auto`) behind the real image, and SHALL remove that placeholder once the real image loads. Non-priority images SHALL NOT render a placeholder.

#### Scenario: Placeholder renders behind the image

- **WHEN** a priority Cloudinary image first renders
- **THEN** the wrapper renders a placeholder `<img>` with the tiny blurred URL, an empty `alt`, `aria-hidden="true"`, and blur/scale styling
- **AND** the real image remains visible and is not hidden behind an opacity transition that depends on hydration

#### Scenario: Placeholder is removed on load

- **WHEN** the real priority image fires its `onload` event
- **THEN** the placeholder is removed from the rendered output

#### Scenario: Blur-up is for priority images only

- **WHEN** `FigureImage` renders a non-priority image, or a priority image whose source is not Cloudinary
- **THEN** no blur-up placeholder is rendered

### Requirement: useCloudinaryImage hook consolidates variants

A `useCloudinaryImage(src, options)` hook SHALL centralize Cloudinary URL transformations and variant generation, so components do not manage transformer token math themselves.

#### Scenario: Hook returns variants

- **WHEN** called with a Cloudinary URL and a `{ widths, sizes }` options object
- **THEN** it returns `{ src, srcSet, sizes, lqip, isCloudinary }` derived from the input
- **AND** `srcSet` is undefined when no variants can be generated

#### Scenario: Hook skips transformations for non-Cloudinary URLs

- **WHEN** called with a URL not matching the Cloudinary pattern
- **THEN** it returns `{ src: <original>, srcSet: undefined, sizes: undefined, lqip: undefined, isCloudinary: false }` and does not modify the URL

### Requirement: Existing users continue to work

The change SHALL NOT alter the public API of `FigureImage` beyond adding new optional props. Existing call sites render unchanged when the new props are unspecified.

#### Scenario: Backward-compatible defaults

- **WHEN** `<FigureImage image={image} />` is rendered with no other props, as in the renderer and gallery
- **THEN** the component still emits the inline `w_400`/`w_800`/`w_1200`/`w_1600` srcset, the default `sizes` attribute, and lazy loading

#### Scenario: No breaking change in tree shape

- **WHEN** inspecting the canonical `ContentTree`
- **THEN** the `image` block has the same `src`, `alt`, `caption`, `width`, and `height` fields as before
